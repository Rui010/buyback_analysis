# 自社株買い案件・イベント 下流提供契約（協議案）

## 1. 位置づけ

`buyback_analysis`から`buyback_app`への提供境界である。上流設計は
[Phase 1](../buyback_plan_event_linking_design.md)を参照する。下流合意前に同期対象へ追加しない。

## 2. 提供データ

| データ | 用途 |
|---|---|
| `buyback_plans` | 安定案件IDと起点 |
| `buyback_plan_projections` | 一覧・集計用現在値 |
| `buyback_events` | 採用中イベント、引用、抽出値 |
| `buyback_event_link_decisions` | 状態、候補、根拠、矛盾、履歴 |
| provenanceテーブル | 原典・run・結果版。同期要否は別途合意 |

## 3. 利用規則

- 一覧、実績、進捗率、完了判定にはprojectionだけを使う。
- 未確定イベントを案件へ割り当てず、案件数・金額へ加算しない。
- 未確定件数、候補、成立・不足根拠、矛盾、ルール版を品質情報として提供する。
- URL、案件ID、enum、単位、日付の意味を同期時に変更しない。
- 判定とprojectionの中間状態を公開しない。

上流はprojectionルール版、入力イベントfingerprint、計算日時、リンクルール版、判定日時を
提供する。

## 4. 実装前に合意する事項

現行同期はallowlist及びTRUNCATE + APPENDのため、次を両リポジトリで確定する。

- PostgreSQL DDL、外部キー、親子同期順序
- append-only履歴の全件同期又は現行VIEW提供
- TRUNCATE中の参照不整合を公開しない切替方法
- provenanceテーブルの同期要否
- 既存テーブルとの並行提供期間と読取切替条件

## 5. 受入条件

- 1案件が一覧の1行になる。
- 複数イベント文書を重複案件として表示しない。
- 未確定イベントが集計へ混入せず、診断可能である。
- 上流IDを維持し、同期再実行で重複しない。
- 切替前に代表fixtureを両側で検証する。

本書は協議案であり、同期又は本番反映の許可ではない。
